## 1. 研究目标与阶段边界

核心问题:**已经发现的 Head 级差异,能否转化为更好的 KV 表示或预算策略,并最终产生存储/搬运或计算收益?**

V2 已支持相对 Head 画像/RoPE 响应和具体 CKA 配对关系跨输入复现;表示与 Attention 的主要关联保留在固定 Head 画像之间,输入残差关系较弱.这支持检验固定先验的用途,尚未证明固定子空间/共享变换或差异化预算有效.

| 阶段 | 研究问题 | 当前范围 |
|---|---|---|
| V3-A | 固定 PCA 基能否跨输入复用?共享基代价多大?同字节下差异化维度是否有优势? | 首轮及后续小规模诊断已完成，见第 13～18 节 |
| V3-B | 压缩同一范围的 K 或 V，对不同 Head 的 Attention 和模型输出影响是否不同? | 采集与落盘链路通过小模型端到端验证，真实 Calib/Validation 未启动，见第 21 节 |
| V3-C | Dense 全量读取下,Head 画像能否额外改善驻留与搬运? | 最小模型已完成，默认等频扫描未见 Head 特有收益，见第 19/20 节 |
| 后续架构 | 哪种机制值得实现为专用硬件? | 根据前述实验证据决定,目前不设计加速器 |

V3-A 首轮只研究 **维度截断**,不同时搜索量化位宽/CKA 分组/跨 Head 对齐/熵编码或跨层预算.K_post 与 V 分开拟合和评价.低有效秩不是直接分配预算的依据;同输入 PCA 误差主要重述已有谱,只作为 Oracle 参照.

## 4. 均值/基的拟合与误差定义

### 4.1 固定均值与一致的拟合目标

以下对 K_post/V 分别执行.令 a=(Layer,KV Head),D=128,输入 i 的中段统计为 N_i/μ_ia/C_ia,C 使用总体协方差 `ddof=0`.

Calib 中六个条件等权,条件内来源等权;每条输入内的 Token 按其总体统计计入,但不因 32K 含更多 Token 就给该输入更高权重.记相应权重为 w_i,则:

$$\mu_a^f=\sum_{i\in Calib}w_i\mu_{ia},$$
$$G_a=\sum_{i\in Calib}w_i\left[C_{ia}+(\mu_{ia}-\mu_a^f)(\mu_{ia}-\mu_a^f)^\top\right],\qquad
s_a=\sum_{i\in Calib}w_i\left[\operatorname{tr}(C_{ia})+\|\mu_{ia}\|_2^2\right].$$

不能仅平均 C 而漏掉输入均值差项.所有固定方案使用同一个 **Calib 逐 Head 均值 μ_a^f**,不改变均值共享粒度,也不免费使用测试输入自身均值.s_a 为冻结的校准能量尺度,不随验证/测试输入更新.

主目标为来源/条件/Layer/Head 等权的 **校准能量归一化 MSE,e_ia/s_a**.Per-Head 基取 G_a 的特征向量;共享组基取 `mean_a(G_a/s_a)` 的特征向量.这样各策略优化同一目标,避免高幅值 Head 自动主导共享基;逐 Head 常数归一化不改变 Per-Head 本征基.零能量 Head 的相对误差标记无效并保留绝对误差,不用任意小常数伪造比值.

读取的 FP32 moments 在 FP64 中聚合和求解,协方差对称化及微小负谱容差沿用 V2.各 r 使用同一完整本征基的前缀,固定 `r∈{16,32,48,64,80,96,112,128}`,不逐 rank 改变拟合数据.

### 4.2 重建与解析误差

令 U_ar∈R^(128×r) 为正交列基,P_ar=U_ar U_arᵀ:

$$\hat X=(X-\mu_a^f)P_{ar}+\mu_a^f,$$
$$e_{ia}(r)=\operatorname{tr}[(I-P_{ar})C_{ia}]
 +\|(\mu_{ia}-\mu_a^f)^\top(I-P_{ar})\|_2^2.$$

e 是每 Token 的平方 L2 重建误差,Frobenius 平方误差为 N_i e,Frobenius 误差为 √(N_i e).另报告标准相对 Frobenius 误差 `sqrt(e/[tr(C_ia)+||μ_ia||²])`;它使用测试输入自身能量作为评价分母,**不用于拟合或选择预算**.所有方案分母一致,原始能量不随重建更新.

除总体均值外,保存每输入/Layer/Head 的误差/按条件的结果及输入内 Head 误差 P90;P90 在每输入的 256 个主指标 e/s 上计算,再按来源/条件汇总,防止少数 Head 的损失被均值掩盖.r90/有效秩和 RCO 只作既有画像对照,不再展开参数搜索.

### 4.3 对照方案

| 方案 | 均值与基 | 用途 |
|---|---|---|
| 原始 BF16 | 不压缩 | 原始表示/误差零和字节基线 |
| 同均值最优投影 Oracle | 固定 μ_a^f;对目标输入 M_ia=C_ia+(μ_ia−μ_a^f)(μ_ia−μ_a^f)ᵀ 求前 r 个方向 | 主 Oracle,区分固定基复用损失与均值适应 |
| 经典逐输入 PCA Oracle | 目标输入自己的 μ_ia 与 C_ia 本征基 | 更自由的几何下界;误差为 N_iΣ_(j>r)λ_j,不是固定基方案 |
| 固定 Per-Head | 每个 a 独立的 Calib 基 | 主要可部署候选与共享对照 |
| 固定 Layer-shared | 同层八个 Head 共享 128×r 基,均值仍逐 Head | 中间共享粒度 |
| 固定 Global-shared | 全部 Layer/Head 共享一个 128×r 基,K/V 分开,均值仍逐 Head | 共享程度最高的参照 |

Oracle 可以使用目标输入统计,但不参与部署/分组/预算拟合或 Test 上的方法选择,也不把其免费目标基纳入公平压缩收益比较.

本轮"共享基"是在同一个 128 维坐标空间内池化,并非把 Head/Layer 拼接成高维向量后的联合 PCA.后者与 [KVTC 的特征拼接方法](https://arxiv.org/html/2511.01815v2#S3.SS1)相关,但需要跨 Head 统计,维度与预算也不同,首轮不实现.直接共享失败不等于 CKA 关系不可利用,可能还需要对齐变换;那将是有额外成本的新方案.

## 5. V3-A 的三步实验

### A1:固定 Per-Head 基能否跨输入复用

只在 Calib 拟合每个 Head 的均值/尺度和完整基,冻结后计算 Validation 曲线.**r=64 是预先指定的主维度**,r=32/96 是辅助预算,其他 r 用于描述曲线和数值检查,不在 Test 上挑最优维度.

主要比较固定 Per-Head 与同均值 Oracle 的误差差距;经典逐输入 PCA 用于说明额外均值适应的下界,不能把两种 Oracle 混为纯粹的基泛化差距.报告各条件/逐层及最差 Head 的偏离,检查误差画像是否跨输入保持,而非只再次确认低秩 Head 的 Oracle 谱尾较小.

按第 7 节报告 Validation 是否达到"接近 Oracle"的标准,完成 A2/A3 的验证集决策后再统一开启 Test.未达该标准仅表示固定基与 Oracle 差距较大,不单独否定固定基在存储/参数或其他误差目标下的全部用途;仍保留既定 A2/A3 的诊断结果,不自动增加 Calib/改用测试均值或替换失败输入.

### A2:共享基的误差代价与参数节省

同一 r/同一 μ_a^f/同一能量尺度/同一数据范围,比较 Per-Head/Layer-shared/Global-shared.主比较仍为 r=64.

报告共享基相对 Per-Head 的误差增量及其在各 Head/任务中的分布,另列基矩阵节省字节.**同 r 下系数载荷相同,模型常驻参数不同,不能称为已匹配完整总成本.** 用 Validation 按第 7 节标准选择是否存在可接受的共享粒度,完成全部验证集决策后再统一开启 Test;若两种共享都通过,优先选参数更少的方案,不按 Test 结果挑选.

首轮不根据 Test CKA 重新分组,不做全部 Head 子集搜索或 Procrustes 对齐.共享被少量 Head 明显拖累时保留反例,作为是否值得另开分组实验的依据.

### A3:相同字节上限下的差异化维度分配

**先固定使用 Per-Head 基**,避免同时混入共享粒度和跨层预算.K/V 独立预算,每层仅在其八个 KV Head 之间分配:

$$r_{lh}\in\{16,32,48,64,80,96,112,128\},\qquad \sum_h r_{lh}\leq8r_0,\qquad r_0\in\{32,64,96\}.$$

以 r_0=64 为唯一主预算,32/96 为预先规定的敏感性检查.Calib 曲线 `J_lh(r)=Σ_i w_i e_i,lh(r)/s_lh` 决定分配,采用每层八个 Head 的离散最小化,目标为各 Head 等权平均误差;不按有效秩/测试误差或 RCO 直接分配.所有输入使用同一套冻结 r_lh,不在每条输入上自适应.

比较两组:统一 `r_lh=r_0`,以及 Head-aware 分配.先保留每层 `Σr=8r_0` 的等系数预算结果作诊断,再按第 6 节补足真实元数据差额,形成 **模型常驻字节和每请求缓存字节均不超过统一方案**的主结果.Calib 上不劣于统一分配主要来自优化定义,不是验证证据;必须在 Validation 和冻结的 Test 上检查收益是否保持.

A2 的共享赢家不自动组合进入 A3;组合方案需单独核算基成本及预算,待首轮结果后再决定.

## 6. 同字节预算与精度口径

### 6.1 两种证据层级

1. **理想投影与预算模型.** 主解析误差使用 FP64 正交投影,不包含系数舍入;载荷预算按 BF16 系数/FP32 存储基和均值建模.结果只能称"给定编码预算模型下的理想重建收益",不能称实测压缩质量或加速.
2. **已有向量上的真实编码/解码检查.** 对评估输入的相同 448 个中段原始向量,使用 FP32 基/均值计算并保存 BF16 系数,按同一精度路径重建,测量额外舍入误差及数组字节.所有方法用同一数据和精度;该结果不替代完整中段的 BF16 系数误差,也不证明模型质量.

FP64 分析参考基不计入部署参数;FP32 基/均值才计入模型常驻成本.不能给候选方案使用理想误差,却用已舍入误差评价对照.NPZ 压缩文件大小和研究数值包大小不作为 KV 编码压缩率.

### 6.2 字节公式

以下仅计算 Prefill 缓存,不包含后续新增 Decode KV.每种表示单独计数,L=32/H=8/D=128,N=T−128.K/V 合计必须相加,K_pre 与 K_post 是互斥候选路径,不同时作为 Cache 载荷累加.

$$B_{cache,i}=2N_i\sum_{l,h}r_{lh}+2\cdot128\cdot LHD+B_{meta,cache,i},$$
$$B_\mu=4LHD,\qquad
B_U^{head}=4D\sum_{l,h}r_{lh},\quad
B_U^{layer}=4D\sum_l\max_h r_{lh},\quad
B_U^{global}=4D\max_{l,h}r_{lh}.$$

基的各列取同一组内最大 r 的前缀.首尾保护区为 **8 MiB/表示/请求**,均值为 **128 KiB/表示**.均匀 r=64 时 Per-Head/Layer-shared/Global-shared 的基分别为 **8 MiB/1 MiB/32 KiB/表示**.原始 BF16 基线为 `B_dense,i=2T_iLHD`,真实字节比较不能只计算中段系数而漏掉保护区.

新增表示参数的模型常驻成本为 `B_model=B_U+B_μ+B_meta,model`,KV 表示相关总驻留为 `B_model+Σ_i B_cache,i`;原模型权重和运行工作区是另列的共同成本,不包含在该式中.同时展示 M=1/4/16 个缓存共享同一参数时的账面总量;不得默认无限摊销,也不将这些 M 当成已实测并发或吞吐.

冻结的 rank 表与静态布局信息归入 B_meta,model,一份参数只计一次:统一预算只需一个 uint16 rank,非统一预算需 L×H 个 uint16 rank.每请求的长度/布局标识等归入 B_meta,cache;offset 若由 rank/T 与固定布局推导则不另存,若实际保存则按其静态/请求归属完整计入.共同的形状/精度/范围等字段对各方案按相同规则计数;不能给统一方案人为添加冗余元数据来凑等预算.

A3 在等系数解上,若非统一元数据导致超出统一方案的模型字节上限,就按 **Calib 归一化误差增量最小**的顺序删除 16 维块,直到满足两个字节上限,且不增加其他层预算.Per-Head 删除一个 16 维块可减少 8 KiB 的 FP32 基,通常足以覆盖 rank 表差额,但仍按实际字段计算.所有维度至少为 16,离散预算余量单列,不用未使用填充伪造"恰好相等".此修正不依赖 Validation/Test 的误差或上下文长度.

- 来源划分/PG19 Pair 归属和 `(sample,Layer,KV Head,scope)` 对齐;无缺失或重复,不混入其他表示/范围.

## 8. RoPE/功能验证及后续路线

RoPE 补充实验在相同 448 位置比较:真实 K_pre 上压缩后恢复 RoPE/K_post 直接压缩/逐位置逆 RoPE 后压缩再恢复.第三条首先是数值一致性与代价对照;精确算术下的对应关系与 BF16 旋转舍入要分开.使用实际绝对位置及同一 RoPE 参数,完整 rank 先测变换舍入底噪,再分析截断误差,不用单个共享逆旋转替代逐位置处理.

该补充实验沿用同一来源划分,从 Calib 的同 448 位置分别拟合各路径的均值与基;最终统一以原始 K_post 为误差目标,并使用该范围的 Calib K_post 能量尺度.它只能对抽样范围作结论,不与全量 K_post 基混比,不据此改变主实验划分或保护区.Pre-RoPE 更低秩也不保证 Attention 可直接在低维空间计算,因为位置旋转通常不能与投影交换.

A 出现固定基或预算的可复现优势后,可先对少量 Head 开展 V3-B,不必等待全部扩展方案.保持其余 Head 与输入轨迹不变,K/V 分开扰动,一个物理 KV Head 对应四个 GQA Query Head.局部固定 Q 的 Attention 误差/传播后的模型 Logits 变化及任务质量分层验证;"同维度"不能冒充"同重建误差".现有工件没有保存完整 Q/Cache/模型 Logits,需要小规模回放及明确的干预路径,不改变原只读采集语义.

V3-C 后续可比较 Dense/真实 Attention Top-K 的 Oracle 与仅用过去信息的 Profile-aware 策略.模拟应计入重排/读写及搬运成本,优先研究分层驻留与预取;Trace 字节和操作量估算不能称实测 DRAM 流量或 Decode 延迟.是否推进该路线及最终硬件架构,待前序结果后决定.

### 15.1 目的与范围

**本文"迁移损失"统指固定基相对逐输入 Oracle 的差距,可能包含拟合内已存在的固定基折中,不全部等同于拟合外泛化损失.** U^f 优化多条 Calib 输入的加权平均误差,逐输入 Oracle 分别优化每条输入;即使拟合完全正确,Calib 内也可能有明显差距.Calib 内差距大且拟合外同条件结果接近,更符合共用方向的固有代价;只有拟合内小/拟合外同条件明显增大,才更提示来源差异/估计或泛化问题.

### 15.2 保持 A1 的比较对象和误差口径

以下对每个表示/坐标 a=(Layer,KV Head) 分别计算,省略 a.沿用第 4 节,令:

$$\delta_i=\mu_i-\mu^f,\qquad M_i=C_i+\delta_i\delta_i^\top.$$

固定参考 \(\,U_r^f\,\) 仍为原 Calib 矩阵 G 的前 r 个方向;\(\,U_{i,r}^{M}\,\) 为输入 i 的 M_i 前 r 个方向,投影分别为 \(P_r^f\)/\(P_{i,r}^{M}\).**主角度主比较使用 M_i 的最优子空间,不能用 C_i 的经典 PCA 基替代 A1 的同均值 Oracle.**

以原有主指标的差值定义迁移损失:

$$d_i(r)=\frac{e_i^f(r)-e_i^{oracle}(r)}{s}
=\frac{\operatorname{tr}[(P_{i,r}^{M}-P_r^f)M_i]}{s}\geq0.$$

d 是绝对的校准能量归一化差,不是误差增幅百分比.原 A1 的相对增幅仍按聚合误差之比计算,继续保留;关联分析以 d 为主,避免小 Oracle 分母放大相对倍数.Oracle 近零沿用原数值容差标记,不补任意小常数.所有原门槛保持不变.

另求 \(U_{i,r}^{C}\) 作中心化结构对照;用原 Calib 权重计算 \(G_C=\sum w_iC_i\)/\(G_\mu=\sum w_i\delta_i\delta_i^\top\),验证 \(G=G_C+G_\mu\),并求 G_C 的参考子空间.G_C 只用于检查均值项是否改变参考方向,不替换原 G,不作为新压缩方案.

### 15.3 主角度/重合度与能量损失

对任意两个正交列基 \(U_A,U_B\in\mathbb R^{128\times r}\),计算:

$$\sigma_j=\sigma_j(U_A^\top U_B),\qquad
\theta_j=\arccos(\sigma_j),\qquad 0\leq\theta_1\leq\cdots\leq\theta_r\leq\pi/2,$$
$$S_r(A,B)=\frac1r\sum_j\cos^2\theta_j
=\frac{\|U_A^\top U_B\|_F^2}{r}
=\frac{\operatorname{tr}(P_AP_B)}{r}.$$

U 的行对应 128 个特征维,不能使用 Token 轴的左奇异向量;不同输入的 N 可以不同,不要求逐 Token 对齐.

角度计算用弧度/展示用度,保存主比较的完整角度谱,摘要用中位角度和最大角度;最大角度不单独决定"稳定/不稳定".浮点越界按数值容差处理.若复用 [SciPy 的主角度接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.linalg.subspace_angles.html),须统一其降序输出与本文升序约定;无需为此新增依赖.

S=1 表示子空间相同,S=0 表示正交,且 \(1-S=\|P_A-P_B\|_F^2/(2r)\),不再额外定义重复的距离指标.128 维内两个独立均匀随机 r 维子空间的 S 期望为 r/128;因此 16/32/64 的几何参照分别为 0.125/0.25/0.5,不能直接比较不同 r 的原始 S 大小,也不将超过随机参照当作可部署标准.

**子空间内的符号变化/主成分换序或正交旋转不改变投影.** 本轮不逐列匹配 PC 编号来判定迁移失败.同时记录参考端 G/目标端 M_i 在截断处的 \(\lambda_r,\lambda_{r+1},\lambda_r-\lambda_{r+1}\);中心化对照对应记录 G_C/C_i 的相同信息.角度较大可能与任一端谱边界不够唯一或稳定有关.近重根时前 r 维子空间可能对微扰敏感,FP64 求解也不能恢复 FP32 moments 已丢失的精度.不给谱间隙调阈值来筛除不利样本.

为检验"变化的方向是否携带重要能量",对同一个 d 作两种恒等分解,不另建压缩目标:

$$d_i=d_i^{C}+d_i^{\mu},\qquad
d_i^{C}=\frac{\operatorname{tr}[(P_i^M-P^f)C_i]}s,\qquad
d_i^\mu=\frac{\delta_i^\top(P_i^M-P^f)\delta_i}s.$$

两部分可正可负,必须保留符号;P_i^M 优化的是两项之和,不能将分量强行解释为非负"原因占比".配合 \(U_i^M\) 与 \(U_i^C\)/G 与 G_C 的角度,判断均值项对最优方向及净损失的影响.

再令 M_i 的完整谱为 \((\lambda_j,u_j)\),\(a_j=\|(U_r^f)^\top u_j\|_2^2\),则:

$$d_i=L_i-B_i,\qquad
L_i=\frac{\sum_{j\leq r}\lambda_j(1-a_j)}s,\qquad
B_i=\frac{\sum_{j>r}\lambda_ja_j}s.$$

L 表示未覆盖的目标主方向能量,B 表示固定基从其余方向获取的补偿能量;同时有 \(\sum_{j\leq r}(1-a_j)=r(1-S)\).这把几何变化与原 A1 差距直接连起来:大角度若主要出现在弱方向,或谱边界接近导致 L/B 相抵,净误差差距仍可能很小.近重根时 L/B 的具体拆分也受方向选择影响,解释应以净差 d 和谱边界为准.两种分解是同一误差的重表达,用于定位和验算,不能将恒等式成立当作额外的独立假设验证.

### 15.5 汇总/关联与解释规则

单输入主比较沿用输入内 256 个坐标等权/条件内来源等权/六条件等权,保留完整 Layer/Head 表.每层分别给出八个 Head 的"校准基对齐度"(平均 S/d)与"输入间稳定性"(同条件输入对平均 S),不将这两种含义合并为一个好坏分数.K/V 按相同输入和坐标作成对比较;不把 K 子空间与 V 子空间直接相乘来解释各自漂移.

**主关联使用 r=64,在每个 Layer/Head 内跨该组 20 条输入计算普通 Spearman(1−S,d)**,每条输入在该相关中等权;这与前述六条件等权的均值汇总是不同的统计量,不将其称为条件等权相关.报告系数分布/方向和有效输入/坐标数,不将跨层/跨 Head 混合的一个相关系数当作解释.同时对两个原始量各自减去所属条件在该坐标内的均值,再计算 Spearman 作为敏感性检查,区分条件间差异与条件内变化;这只是解释性统计,不是预测模型.常量序列标记无效,2/4 条的单条件不单独作强相关结论.

r64 的"校准基对逐输入"主比较均值及总体相关均值沿用 2,000 次/seed=20261113 的条件内来源 Bootstrap,**只对历史 Validation/Test 分别计算,Calib 只作描述性对照**.同一组内 K/V/各坐标和指标共用来源抽样索引,PG19 Pair 两长度共用抽样.相关均值先在每个坐标算系数,再对有效坐标等权;每次重采样重新计算相关及条件均值,固定原 Calib 参数和 G_C,不重拟合,区间不包含 Calib 拟合不确定性.报告有效 Bootstrap 数及有效坐标数,不作逐 Head 显著性筛选.16/32 及输入对汇总仅作描述,不为输入对另算显著性,也不以成百上千个输入对冒充独立来源样本.

| 观察组合 | 可支持的解释与限制 |
|---|---|
| 失配 1−S 较大/d 较大,且主方向净能量损失明显 | 与有重建代价的子空间变化相符;仍需说明发生在哪些条件与 Head |
| 角度较大但 d 小,谱边界接近或 L/B 大致相抵 | 弱方向/近重根或边界交换可能占主导,不能仅凭角度判定实质迁移失败 |
| S 较高但 d 或 A1 相对增幅仍大 | 检查少数高能方向及 Oracle 分母;重合度不能替代能量误差 |
| 中心化对照更稳定,而 M 子空间变化明显,均值相关分解也发生变化 | 均值项改变最优方向的证据增强;分量有符号,不能直接宣称解释了某个百分比 |
| 同条件相互迁移较好/跨条件较差,且 Calib 内也有明显折中 | 与多条件共用一个固定基的折中相符,不等于已证明某种分组压缩有效 |
| Calib 内差距已大,拟合外同条件与之接近 | 更符合一套固定方向兼顾不同输入的代价,不能直接称为泛化失败 |
| Calib 内差距小/拟合外在相同条件下变大 | 提示来源差异或估计/泛化问题;现有数据不足以唯一确定原因 |

正文同时保留已有 A1 反例(如 K 的 L18/H3/V 的 L29/H7)和不符合上述直觉的反例,不能只选角度与误差一致的 Head.相关/恒等分解和输入对模式只能提供机制诊断,不能分别当作因果证明.

RULER 沿用消费前 6 个 Token 的协议,检查 s=5;GovReport/PG19 消费前 256 个 Token,**每步编码并记录紧凑误差**,在 s=31/255 额外检查位置/历史系数和已保存 Prompt 行的一致性.此前 V2 的两个单 Token 检查点不够替代这 256 个新 Token 的连续编码验证.回放仍核对原 B1 预测,但因模型使用 Dense Cache,这一检查只证明只读性和来源对齐,不证明压缩后的生成质量.

### 16.4 是否需要恢复 K_post

**兼容现有 SDPA/FlashAttention 的短期路径需要恢复 D=128 的 K_post.** 实际使用压缩 Cache 时,可按块解码并写入该层的完整 K_post 临时缓冲,再交给现有 Attention;不得一边长期保留原始全量 K_post,一边宣称获得压缩常驻收益.直接将小块交给现有 Kernel 并不能自动得到完整 Attention,需要新 Kernel/跨块归一化,不在本轮范围.本轮只在旁路验证这个恢复过程和成本,不接入模型.

"不恢复"仅做代数/操作量可行性检查.令当前 Query 已经 RoPE 后为 q_i,历史位置为 p,理想重建为:

$$\hat k_p^{post}=R_p(\mu+Uz_p),\qquad
q_i^\top\hat k_p^{post}
= (U^\top R_p^\top q_i)^\top z_p+q_i^\top R_p\mu.$$

必须保留均值项.R_p 随历史位置改变,通常不能只对 q_i 做一次 r 维投影后和所有 z_p 点积;也不能以同一个 r×r 旋转替代 R_p.可只在小模型/合成向量中核对该等式与显式恢复点积,不展开真实模型 Attention 敏感性实验.此等式适用于给定线性旋转及未舍入的重建,不保证复现实际 BF16 逐算子舍入.若免恢复实现需要逐位置 D×r 投影,其成本必须据实报告;不给出 O(Nr) Attention 或加速结论,不保存每位置 D×r 的旋转基来隐藏空间代价.

### 16.5 存储账本与计算/搬运成本

设已消费 g 个生成 Token,连续位置从 0 开始,L=32/Hkv=8/D=128/r=64.沿用 FP32 U/μ/BF16 系数/保护区.单个候选的编码常驻账本为:

$$B_K(T,g)=2LH\,[r(T-128+g)+128D]+B_{meta,request},$$
$$B_{model}=4LH(Dr+D)+B_{meta,model},\qquad
B_V(T,g)=2LH D(T+g).$$

| Prompt 长度 | 原始 K | r64 编码 K(含保护区) | 原始 K+V | 编码 K+原始 V |
|---|---:|---:|---:|---:|
| 8K | 512 | 260 | 1,024 | 772 |

## 18. K_pre 跨 Head 共享基的小规模对照(已完成)

### 18.1 问题与边界

本轮只问:**同层两个 Head 能否共用一套低维基,以可接受的重建代价减少参数?按重建代价配对,是否比只按 CKA 配对更合适?** V2-C 中 K_pre 对固定参考的 CKA 排序相关约 0.974、Top-7 保留率约 90.4%,说明值得检验具体配对.但原 K_post 的整层共享在 Validation 上比逐 Head 重建误差高 84.344%,第 17 节又显示稳定的压缩难度画像只带来约 4.5% 的预算收益,均提醒我们不能由结构统计直接推导收益.

先检验**同一 128 维坐标系内直接共享基**,最大组大小为 2,不跨层.各 Head 保留自己的固定均值、系数和 Token,不共享系数或合并 Cache.主维度固定 r=64,r=128 仅作正确性检查;不重新搜索 rank/量化精度、不结合第 17 节的非统一维度.不实现 Procrustes/复杂编码器/拼接联合 PCA,也不修改模型推理或新增采集.直接共享的结果不覆盖“经过额外对齐后能否共享”这一后续问题.

CKA 对各 Head 自身的正交坐标变换不敏感,两个 Head 即使具有相近的 Token 结构,主方向仍可能落在不同特征坐标上.因此 CKA 仅作为一个明确的分组对照,是否值得共享由实际误差和完整字节共同判断.

### 18.2 数据与匹配拟合

继续使用第 16.1 节的六条 Calib/六条 Validation,各五个来源,PG19 Pair 成组,保持原 split/ID/位置不变.这十二条均已分析过,本轮仍为探索性复用,不称为新的独立确认,不打开旧 Test,不作来源 Bootstrap 显著性结论.已有 100 条 CKA 结果只作为研究动机;**配对决策仅读取六条 Calib 的已发布 K_pre CKA**,不按全 100 条的平均矩阵或 Validation CKA 选配对,不重算 CKA/置换.

使用 `v3_pre_rope_pilot_20261116_v1/{pilot,validation}` 的完整中段 K_pre N/μ/C,以及原 V2 对齐的 448 位置 K_pre/K_post 原始向量.完整中段用于拟合和理想误差,同 448 位置用于最终 BF16 K_post 检查,两种范围分列.

**本轮新增匹配拟合,不是继续沿用旧基作为唯一对照.** `rope_calibration.npz` 保存了原 60 条 Calib/448 位置的均值与基,但没有保存 K_pre 的拟合矩阵 G;`calibration.npz` 中的 G 则属于 K_post/V,不能替代它.为避免新共享基与旧逐 Head 基的拟合来源不同,本轮只用六条 Calib 的完整中段统计,同时拟合新的逐 Head/共享基.原逐 Head 均值 `μ_lh^f=rope_calibration.mean[0]`、完整中段 K_post 能量尺度 `s_lh=calibration.scale[0]` 保持不变,不改均值共享粒度,不用 Validation 自身均值编码.

令 w_i 沿用六条件/来源等权,FP64 中计算:

$$M_{i,lh}=C_{i,lh}+(\mu_{i,lh}-\mu^f_{lh})(\mu_{i,lh}-\mu^f_{lh})^\top,\qquad
G^{(6)}_{lh}=\sum_{i\in Calib6}w_iM_{i,lh}.$$

逐 Head 基为 G^(6)_lh 的前 r 个本征方向;同层配对 g={a,b} 的共享基为下式的前 r 个本征方向:

$$\bar G_{lg}=\frac12\left(\frac{G^{(6)}_{la}}{s_{la}}+\frac{G^{(6)}_{lb}}{s_{lb}}\right).$$

这保持各 Head 的归一化误差权重一致,包含输入间均值变化项;不是仅平均协方差,也不是把两个 Head 拼成 256 维后降维,不需要完整 Prompt 的跨 Head 互协方差.保存拟合来源、权重和选定参数即可,不复制原始统计或全部候选基.原第 16/17 节的 60 条拟合基另作历史参照,新旧结果不覆盖.

### 18.3 对照与只用 Calib 的配对规则

| 对照 | 基的来源/共享方式 | 用途 |
|---|---|---|
| O64:原冻结逐 Head | 原 60 条 Calib/448 位置,每 Head 独立 | 登记重新拟合前的已有误差,不作为共享增量的唯一分母 |
| I64:匹配逐 Head | 六条 Calib 完整中段,每 Head 独立 | 以下三个共享方案的主误差对照 |
| S-index:固定索引配对 | 每层 (0,1)/(2,3)/(4,5)/(6,7),每对一套新基 | 无数据驱动配对的控制,不称为随机配对 |
| S-CKA:CKA 配对 | 每层选四个互不重叠、覆盖八个 Head 的配对 | 检查仅以相似性决定分组的效果 |
| S-error:重建代价配对 | 相同覆盖约束,按 Calib 的真实共享误差增量选配对 | 主候选,不以 CKA 或有效秩直接代替代价 |

先在每层全部 28 个无序 Head 对上拟合共享基并计算 Calib 代价.定义 J_lh(U)=Σ_i w_i e_i,lh(U)/s_lh,其中 e 使用第 4.2 节的固定均值公式.配对的代价为:

$$\Delta_{l,ab}=\frac12\sum_{h\in\{a,b\}}
\left[J_{lh}(U_{l,ab})-J_{lh}(U^{I}_{lh})\right].$$

S-error 最小化每层四对的 ΣΔ;S-CKA 最大化四对的 Calib 条件等权平均 Observed CKA 之和,Excess CKA 仅保留作对照解释.八个 Head 的完整两两配对仅有 **105 种**,枚举这些固定配对即可,不扩展组大小/跨层或全部子集搜索;不能直接取 CKA 最高四条边而让同一 Head 重复入组.并列按规范化配对 ID 的字典序决胜,所有分组对全部输入固定.

Calib 上的 Δ 理论非负,因为 I64 单独优化各 Head;仅容差内的负值可标为舍入量,超出则检查实现.Validation 的共享增量可以为负,应保留符号,不把它当作实现错误.报告每层 28 对的 CKA–Δ 排序相关及高 CKA/高损失反例,不将 Head 对当作独立来源推断.此处 CKA 来自 448 位置、主 Δ 来自完整中段,范围差异必须标注,不能据弱相关单独判定 CKA 无信息.

三种配对、全部均值/基/rank/精度及预算先冻结,之后统一评估六条 Validation.不根据 Validation 删掉难共享的 Head、选择有利层或改为部分共享.全配对失败时只否定本轮强制覆盖的直接共享方案,不能排除少数配对或带成本对齐仍有潜力.

### 18.4 重建评价与判断

主比较为各 S 相对 **I64** 的完整中段 Pre 域理想误差增幅,同时登记 O64→I64 的拟合变化,不把 S/O64 的差异全部解释为共享收益.按输入内 Layer/Head 等权、再条件/来源等权汇总,报告逐条件、Head P90、逐层/逐 Head、最差绝对误差及最大相对恶化,不能以一对的平均值掩盖其中一个 Head 的损失.

在相同 448 个原始 BF16 向量上,用 FP32 均值/基编码为各 Head 独立的 BF16 系数,恢复到 D=128,再逐位置 RoPE 得到最终 BF16 K_post.理想/实际两套误差均与原 K_post 比较,沿用同一 s;transform-only 底噪单列.这只是抽样的实际编码检查,不替代完整中段 BF16/Decode/模型输出质量.本轮不把 P90 或均值改善换算成质量保证.

候选筛选沿用原 A2 的 **r64 平均误差增幅≤10%、每条件增幅≤25%、实际参数字节更少**;本批只作描述性筛选,不重新判定旧 A2.抽样 BF16 也需按相同分母核验这两条误差界限,不能只用理想结果声称编码候选.所有预定方案均报告,不因未通过而换数据/预算或追加拟合.P90 和个别 Head 若有明显代价须单独讨论,达到上述平均门槛也只说明重建–参数折中可保留,不是部署许可或压缩 Cache 可用性.

实施验证复用第 7.1 节容差/解析与直接重建检查,另覆盖:相同子空间共享无额外理想损失;CKA=1 但主方向经正交变换落在不同坐标子空间时,共享仍可能损失;Calib 同目标非负代价;每层配对互斥且覆盖完整;改变 Validation 不改变参数/配对;实际 FP32 载荷、共享映射及 BF16 系数字节一致.r128 仅检查闭环/舍入,不构造近零误差的相对增幅.

### 18.5 参数、请求字节与计算成本

对每层组集合 $\mathcal G_l$,统一 r64 的字节为:

$$B_U=4Dr\sum_l|\mathcal G_l|,\quad B_\mu=4LHD,\quad
B_{K,i}=2(T_i-128)LHr+2\cdot128LHD+8.$$

### 19.5 可确定的逻辑位置与字节映射

对输入初始长度 T,Decode Step s 消费 `generated_ids[s]`,Query/新 KV 位置 `q=T+s`,可见 Token 数 `N_s=T+s+1`;其预测出的下一个 Token 尚未进入本次 Cache.每条成功轨迹有 `generated_length−1` 个这样的 Forward,不要多算最后一个仅预测的 Token.此次全部位置与候选数组均满足上述关系.

令 P=16,则全量页集合为 `p=0,…,ceil(N_s/P)−1`,Page p 的有效 Token 数为 `n_p=min(P,N_s−Pp)`.GQA 映射是 `kv_head=floor(query_head/4)`;KV 对象应至少用 `(sample_id,layer_id,kv_head,K或V,page_id)` 标识,不能跨 Head/Layer/输入合并相同 page_id.

BF16/D=128 下,每页有效 K 或 V 载荷为 `256n_p B`,K+V 配对为 `512n_p B`;完整 16 Token 页分别是 **4 KiB/8 KiB**.末页有效载荷与分配/搬运整页容量分开:若按整页槽位分配 SRAM,即使未满也需支付整页容量;是否整页搬运、对齐或只传有效行仍待协议确定.新 Token 每层每 KV Head 追加 K+V **512 B**,全模型合计 **128 KiB**,不等于实际 LPDDR 写事务数或写放大量.

在“每个物理 KV 元素对四个 Query Head 复用、K/V 各读一次”的明确假设下,一次 Decode 全模型的有效 K+V 逻辑读取为 `2×L×Hkv×D×2×N_s = 131,072N_s B`.按完整页传输则为 `8,192×L×Hkv×ceil(N_s/16) B`.这些是推导值,不是测量值;不能用 Hq=32 代替 Hkv=8 直接多计四倍.若硬件分开计算四个 Query 导致重复读取,应显式建模其放大量.

当前新生成的一行 KV 可能直接从片上计算单元转发,无需再从 LPDDR 读取,但完整后备 KV 仍需按规定写回;Prefill 写入、Decode 追加、冷启动/预热、部分页更新和最终回写均需独立定义.初始化 Cache 的读取/写入不能因为 Trace 从 Decode 开始而免费忽略.

### 19.6 需要冻结的模型假设与后续边界

现有 Reader 可复用:来源索引用 [b1_reader.py](../../experiments/head_analysis/storage/b1_reader.py) 的 `load_completed_run_set`;原始 Page 集合读取可参考 [page_rco.py](../../experiments/head_analysis/analysis/page_rco.py) 的 `_load_sample_arrays`,它只提供排名/候选数/有效位,不含质量;Mass/Coverage 从原 NPZ 读取方式见 [b1_offline.py](../../experiments/head_analysis/analysis/b1_offline.py).这些函数不是物理访存模拟器.未来按分片流式读取即可,无需先拼接全部巨型标量数组,当前未改代码或抽象接口.

下一份最小模拟计划需要先明确:层/Head/Page/K-V 的访问顺序与分块、GQA 片上复用、SRAM 容量中数据/标签/控制元数据的计账、初始状态、缺页后的插入或旁路、末页/追加的写回和转发、DMA 合并及延迟/带宽参数.物理顺序应标为拟定 NPU 数据流假设,不能称从 B1 实测还原.这些缺项优先通过目标数据流定义解决;为此补采 GPU Attention 分数并不能得到 NPU 的总线行为.

候选基线保留无 SRAM、全局 LRU、等额 per-Head LRU、固定驻留+旁路读取;未来 Oracle 仅作为不可部署的参照.实际策略及容量/TTL/刷新频率均未冻结.全局循环扫描可能使 LRU 抖动,因此不能把固定驻留对 LRU 的收益自动归因于 Head 稳定性.同样大小/次数/服务代价的 Dense 页,任意同容量常驻集合在简化模型下可节省同样的读取量;Head-aware 必须解释额外复用、调度或成本差异,不能只用 Attention 重要性代替访问热度.

若以后使用 Head Profile,只能由规定的 Calib/历史数据建立;已有全 100 条聚合 Profile 不能直接拿来证明在同 100 条上的拟合外收益,也不能把当前 Step 计算后的 Top-K 用作该步的免费预测.保持全部 KV 时缓存模型主要评估流量/等待;若决定不取回某些页,即改变了当前 Dense 范围,需另行批准质量验证.真实延迟/能耗仍需硬件参数和验证,并核查权重等其他瓶颈.

**审计结论:**现有 B1 数据足以进入 Dense 全量逻辑需求与参数化存储模型的方案设计,没有必须补采的模型中间量.它不足以直接计算实测 LPDDR/DMA/能耗或任意删页后的模型质量,也未证明 RCO 画像对 Dense 缓存有额外收益.审计正常结束,未新增采集或修改研究代码;后续最小计划与获批实现见第 20 节.

## 20. 最小 Dense 存储模拟计划(2026-11-17)

### 20.1 第一轮要回答的问题

先建立一个可手算、可核验的 **Batch=1 Dense Decode 存储模型**,回答三件事:统一循环扫描下 LRU 和固定驻留分别能省多少片外读取;相同 SRAM 字节预算下,按离线 RCO 分配驻留配额是否有额外收益;这些收益是否只是通用驻留机制或管理元数据差异造成的.

全部必要 KV 都读取,不引入稀疏、量化或 Pre-RoPE 编码.本轮不实现预取、异步 DMA、Bank 冲突、完整时钟级 NPU 或模型质量干预.具体芯片仍未选定;以下为明确的研究模型假设,不是已有硬件事实.本计划不改 B1 的 RCO/Attention 指标或原 V3-A 门槛,也不沿用重建实验的 5% 作为访存门槛.

**预期的零增益关系须事先登记:**同一 Dense 数据流中,若驻留页等大小、每步等频读取,只改变其 Head 身份不应改变所省字节.第一轮要能正确验证这一关系;若成立,及时收束这一简化模型,不继续追加 TTL/刷新/配额搜索来制造 Head-aware 收益.正结果必须有额外复用或服务成本差异的机制解释.

### 20.2 数据与推进顺序

1. **小合成序列:**验证 Page/追加/容量/策略/字节规则,显式逐请求执行作参考.
2. **六条 Calib:**复用第 16.1 节固定六条,使用原 B1 保存的完整 Decode 轨迹,不是仅 256 步的 Pre-RoPE 回放;完成真实形状、预算和加速计数核对.

Head 画像仅读取原 `v3_a_20261113_v1/split.json` 中 **Calib 的 36 条长文本输入**:GovReport 两条件各 12 条,PG19 两条件各 6 条,共 30 个来源.使用 B1 `head_profiles.npz` 中逐样本 `all_visible,k=32,Δ=32,rco_raw_mean`,四个长文本条件等权、条件内来源等权;RULER 六步不具备该 Δ,不补零.只用原 RCO,不重新定义稳定性或二值分类.数值包虽包含全部样本,拟合严格按 Calib ID 选择,不把全 100 条平均 Profile 用于选择.

不打开旧 Test 来挑策略,不自动扩至 100 条.若默认模型下的等价关系已解释结果,十二条即可收束;更大的集合或新数据流机制再另行决定.本节容量、策略和参数表在计算候选结果前固定;Calib 阶段只允许修复正确性问题,不按结果更换参数.实际 Validation 前保存已冻结配置及画像/配额.

### 20.3 默认数据流与初始化

模型维度/位置沿用第 19.5 节.逻辑缓存对象固定为 `(layer,kv_head,page_id)` 的 **K+V 配对页**,一个完整页为 `[16,2,128] BF16=8,192 B`,各 Token 的 K/V 共 512 B.这是拟定的 LPDDR 配对页布局,不是对原 GPU 物理布局的测量.输入之间清空状态,不跨请求复用.

每步按 `Layer 0→31 / KV Head 0→7 / Page ID 递增` 执行.一页 K/V 为对应四个 Query Head 共享读取一次,不按 Hq 重复读取;全部页仍参与 Attention.将整页所需 K/V 配对搬入片上是一种数据流假设,本轮不另外比较 K/V 分离存储或不同 Query 分组顺序.

Prefill 作为共同启动成本:把全部 Prompt KV 按配对页流式写入 LPDDR,末页只写有效行,**Decode 起点 SRAM 留存为空**.Prefill 写入字节/事务单列,不免费预热缓存,也不把空缓存说成自然硬件的必然状态.若以后比较 Prefill 预热,需单独固定其写入/替换和容量成本.

Decode Step s 的可见域仍为 `N_s=T+s+1`.进入每层时,该层八个 Head 的新 K/V 行已经生成,合计 4 KiB 暂存;各行先 write-through 到 LPDDR.若其所在页已驻留,同步更新该页有效行数和数据,**不因写入更新 LRU 顺序**;未驻留则 write-no-allocate.读取该层时,新行直接从片上提供,不重复从 LPDDR 读取;历史行由 SRAM 或缺页搬运取得.预测但尚未消费的 Token 不产生本步 KV 写入.

### 20.4 SRAM 预算与管理字段

扫描专用于本模型的 **KV 存储子系统预算 S={16,32,64} MiB**,32 MiB 为主要展示点,其余两点一并报告,不择优挑容量.它不代表整颗芯片的全部 SRAM;Q/Softmax/输出累加器/权重缓冲等计算单元空间不在该池内,后续系统设计仍需相加.

预算内共同扣除:8 KiB 缺页流式缓冲+4 KiB 当前层新 KV 暂存+256 B 控制区,合计 **12,544 B**.“无缓存”指不留存任何页,仍支付这些流式处理空间.所有驻留页均占完整 8 KiB 槽位,即使其末页尚未填满.

每页基本标签为 16 B:Layer/Head 各 uint16、Page ID uint32、有效行数/flags 各 uint16、4 B 对齐填充.LRU 另有前驱/后继各 uint32,总计 24 B/页.全相联查找先按功能建模,其真实查找时延/能耗不由这个标签预算证明.每 Head LRU 另存 head/tail/occupancy 三个 uint32,共 `12×256=3,072 B`;Profile 固定驻留另存 256 项 uint32 配额,共 1,024 B.不把离线拟合矩阵常驻在硬件中,也不向统一策略收取不需要的 Profile 表费用.

各策略自己的槽位数为 `F=floor((S−12,544−B_policy)/(8,192+B_entry))`,余量单列,不人为填充以凑相同槽位数.容量约束比较的是相同总字节上限,实际数据/标签/策略表/缓冲/余量均报告.采用原始位宽/对齐布局可核对的预算,不把 Python 容器的内存当作硬件 SRAM 成本.

### 20.5 最小策略与身份对照

| 策略 | 具体规则 | 额外策略表/每页标签 |
|---|---|---|
| No-retention | 每次历史页请求均从 LPDDR 取回,不留存 | 0/不分配驻留项 |
| Global-LRU | 全部 Layer/Head 共用 F 个槽;读命中更新顺序,读未命中插入并按 LRU 替换 | 0/24 B |
| Equal-Head-LRU | F 个槽先对 32 层等分,再在各层八 Head 内等分;各子池独立 LRU | 3,072 B/24 B |
| Equal-Pin-Bypass | 同样等分 F 得到 q_lh;固定保留各 Head 的前 q_lh 个逻辑页,首次需求时装入,其余页流式绕过 | 0/16 B,配额由索引和 F 推导 |
| Profile-Pin-Bypass | 层间等分 F,层内按 Calib RCO 排名分配 q_lh;页规则与 Equal-Pin 相同 | 1,024 B/16 B |
| Shifted-Profile-Pin | 将上一策略每层冻结的八个 q 循环移位一位,保持逐层配额总量和配额多重集完全相同;其余规则一致 | 1,024 B/16 B |

所有等分余数按较小 Layer/Head ID 依次分配.Profile 在每层按 RCO 从高到低给固定权重 `8,7,…,1`,同分按较小 Head ID;用 `floor(F_l×w/36)` 后按最大余数补齐该层 F_l,余数同分仍按 Head ID.不搜索权重斜率、Stable 阈值或配额比例,不设“Unstable Head 禁止使用 SRAM”的规则.循环移位直接作用于已经得到的 q,不重新分配余数,不改变元数据或容量.

这是最简单的 **Head 配额候选与身份消融**,没有声称“各 Head 的前几页”就是其 Attention 热点,也没有使用 Top-K 选择 Dense 页.所有未驻留页仍完整取回.Profile 与 Shifted 是主机制比较;Equal-Pin 是重要的通用驻留基线,仅优于 LRU 不能认定利用了 Head 画像.本轮不实现未来 Oracle,也不引入更多替换算法.

### 20.6 缺页、写回与模型化 DMA

每个历史页缺页发起一个逻辑 DMA 读命令,传输该页尚需的全部历史有效行,不合并跨页命令.当前新行由暂存提供;末页装入时把历史行和新行组成完整的有效内容,容量仍按整页支付.新页若仅含当前新行,记为 `forward-only`,不发起零字节 LPDDR 读取;LRU 或固定驻留规则仍决定是否留存该页.

每层每 Head 的新增行固定发起一次 512 B write-through,因此每 Decode Step 共 256 次写命令/128 KiB 写载荷.驻留页始终与后备一致,本模型无脏页驱逐回写.按 64 B 最小搬运对齐核算,512 B 行不会额外扩大;这只是协议假设,并非真实 LPDDR Burst、Bank 或总线事务的测量.Prefill 每配对页一次写命令,有效载荷共 `131,072T B`.

Profile 与 Shifted 每输入开始各从后备存储加载 1,024 B 配额表,记一次模型读命令,与 Prefill 启动成本单列;不能免费省略.其他策略的控制表在 SRAM 初始化,初始化操作计数单列,不虚构 LPDDR 读取.同时报告 `启动写入+配额加载+Decode 读写` 的全程字节,避免只报 Decode 命中而漏掉新增成本.

统计的“DMA 次数”指上述模型命令数,不能称为真实 DRAM Burst 数.不合并、不预取、不重叠执行,避免同时引入多种机制.若未来改变合并/写分配/回写语义,需建立另一明确对照,不能只给 Head-aware 使用更有利的传输规则.

### 20.7 指标、对照与时间解释

主要结果为每输入/条件的 **Decode LPDDR 读字节、写字节、读写合计**,以及相对 No-retention/Equal-Pin/Shifted 的字节差.另保留模型读/写命令数、读命中/历史缺页/forward-only 数、驱逐次数和 SRAM 数据/元数据/缓冲/峰值/余量.逐 Layer/Head 计数保留紧凑数组,不只报总体百分比.

页命中率使用 `H/(H+M)`,H/M 只计需要历史行的页;新页 forward-only 单列,不把新 KV 片上转发当作缓存命中.字节加权命中率为命中所避免的历史有效字节除以相同输入 No-retention 的历史读字节.标签查找、LRU 链更新或配额查询的操作次数单列,当前不把控制成本假定为已验证的零延迟/零能耗.

Prefill 启动写入、第一 Decode Step、其后各步及总计分开,RULER 后五步不称稳态.同一输入中的全部 Step 先累计,再在条件内对输入等权,跨条件均值仅作描述;PG19 Pair 保持配对.不把 Head/页/Step 当作独立来源.本轮没有 Attention Mass Recall 或模型质量“通过”的结论,因为不删除页且不执行实际 Attention Kernel.

时间仅作附属参数化后处理:`t_transfer=(B_read+B_write)/β+(n_read+n_write)τ`.预先给出有效载荷带宽 `β={16,32,64} GB/s`、每模型命令固定开销 `τ={0,100} ns` 六种组合(GB=10^9 B,ns=10^−9 s);均是抽象假设,不映射具体芯片,不按结果更改.它是串行片外搬运服务估计,不含 SRAM 查找/计算/权重访问,不是端到端 Decode 延迟或能耗;τ=0 的带宽项也不能替代完整系统瓶颈分析.模拟器 CPU 墙钟时间只用于评价分析工具开销.

### 20.8 正确性、解析检查与计算规模

参考执行器在小合成序列逐请求运行,至少覆盖:零留存/足够容量、冷启动与其后热状态、Page 边界和未满页、新行转发、驻留末页更新但写不分配、跨输入隔离、GQA 不多计四倍、每策略字节上限、LRU 与固定驻留的循环扫描差异、只改 Validation 不改变 Profile/配额.所有必要历史行必须由缓存或 LPDDR 提供,不能把缺失页当作未访问.

有三个可直接验算的计数关系,均使用整数:

- No-retention 的每输入 Decode 历史读字节 `131,072×[CT+C(C−1)/2]`,新增写字节 `131,072C`;Prefill 写入另计.这里排除了直接转发的当前新行,区别于完整可见域的逻辑字节.
- 若每步所有页只读一次且工作集超过相应 LRU 池的复用距离,循环扫描应得到零历史读命中;超大容量对照则应在装入后保留全部历史行.用合成序列检验,不能把某一结论无条件用于所有容量.
- 若所有固定驻留配额 `q_lh≤floor(T/16)`,所选页都已是完整 Prompt 页,冷启动下缓存节省应为 `8,192F(C−1) B`,写字节不变.Profile 与 Shifted 必须得到完全相同的读/写字节和命令数.默认真实输入的最小完整 Prompt 页数约 450,默认最大配额不超过 57,处于这一可验算范围.

根据已审计的实际 T/C,十二条一次完整扫描约 **16.63 亿**个配对页逻辑请求,100 条约 **128.53 亿**个;均为公式枚举数,未运行缓存策略.因此不保存完整请求流,也不以 Python 对每方案/容量反复循环这些对象作为默认路径.先用小参考执行器核对循环扫描的区间/解析计数,再在已满足上述条件的真实输入上使用完全等价的快速计数.不近似截断 Step,不抽掉 Head/Page;不满足加速条件时明确走参考路径或报告需扩展支持,不能默默套公式.

真实六条 Calib 先核对可见域、末页、预算、No-retention 闭式公式及身份等价关系,再冻结配置/Profile/配额并执行六条 Validation.数值计数和字节恒等式要求精确一致;有理计时换算使用浮点容差.若 Head 身份错位在默认等频条件下产生了不同收益,先按实现或假设不一致排查,不能直接作为研究发现.

### 20.9 实现范围、输出与收束规则

拟仅新增 `analysis/dense_kv_memory.py`、薄入口 `scripts/simulate_dense_kv_memory.py` 和一份必要的合成测试;复用现有 B1 来源 Reader/分片元数据、原 Split/RCO 数值和 common I/O.不新增 Collector/Runner/通用缓存框架或第三方依赖,不改变现有分析接口.真实主路径只需逻辑尺寸/步数和冻结 Head Profile,不重复读取巨型 Scalar/Top-K 数组或加载模型.

## 21. V3-B 小规模方案：全 Token Dense 下的 Head 级量化敏感性（已批准）

### 21.1 问题与边界

第 20 节说明，等频、等大小的 Dense 扫描中，RCO 身份不会自行改变每字节的重复读取次数。可继续检验的机制是：**不同 Head 若能容忍不同精度，是否有机会在输出误差约束下使用不同的实际编码字节？** V2 的有效秩、E16、CKA 和已有 PCA 重建结果都不能代替这个判断。

本轮先回答两个小问题：相同量化侧/位宽/字节成本下，改变哪个 Head 是否导致不同的输出损失；这种敏感性排序能否从六条 Calib 保持到六条 Validation。**相同位宽不等于相同重建误差**，必须同时记录表示误差与输出误差，不能将两者的差异混为纯粹的模型敏感性。

沿用 Llama-3.1-8B-Instruct、BF16、Batch=1、SDPA 和原 B1 输入/生成 ID。所有历史位置及当前 Token 均参与 Attention，不删 Token、不按 Top-K 限制访问、不近似复用历史 Attention。首轮仅干预 **Prompt 历史 KV**；新增 Decode KV 保持 BF16。K 主对照直接量化实际参与 Attention 的 **K_post**，V 单独量化；不加入 PCA、Pre-RoPE 恢复、跨 Head 共享、2 bit 搜索、混合精度分配或硬件实现。Pre-RoPE 的重建优势保留为第 16 节结论，本轮用于隔离量化与输出影响，不检验编码位置优劣。

### 21.3 K/V 分开的固定量化规则

参考 [KIVI 的 K 按通道、V 按 Token 区分](https://arxiv.org/html/2402.02750v2)，采用一个简单的分组线性量化器，不声称复现其完整算法或质量结果。组长固定 **G=32**，位宽固定 **4 bit 主分析、8 bit 较轻扰动对照**，不根据 Validation 改组长、保护区或裁剪阈值。

设 Prompt 长度为 T，量化行数 `Q=32×floor((T−128)/32)`，范围固定为 `[64,64+Q)`。首尾各 64 行、末尾不足 32 行的中段残余以及全部新增 Decode 行均保持 BF16；K/V 使用相同位置范围。该范围不同于原 A1 的完整中段，单独标注，不改写原指标或把保护区零误差混入量化区域主误差。

| 对照 | 发生量化的位置 | 分组 | 其余数据 |
|---|---|---|---|
| BF16 / 旁路对照 | 无 | 无 | 原始 Dense KV |
| K4、K8 | 一个指定 Layer×KV Head 的 Prompt K_post | 每个特征通道沿连续 32 个 Token 一组 | V、其他 Head、保护区和新增 Decode KV 保持原值 |
| V4、V8 | 一个指定 Layer×KV Head 的 Prompt V | 每 Token 沿特征维分为四个连续 32 维组 | K、其他 Head、保护区和新增 Decode KV 保持原值 |

每组从该 Prompt 的真实 BF16 值转 FP32，取 `m=min(x)`、`u=max(x)`、`a=(u−m)/(2^b−1)`；计算 `q=clip(round_to_even((x−m)/a),0,2^b−1)`，恢复为 `x_hat_FP32=m+a×q`，再转 BF16 供原 SDPA 使用。常量组明确为 `a=0,q=0,x_hat=m`，不加任意 epsilon。每组实际保存 **FP32 m 与 FP32 a，共 8 B**，不另收整数 zero-point；不使用百分位裁剪、异常值侧表或预先搜索的旋转。基于当前 Prompt 计算 min/max 是编码的一部分，需计入编码成本，并非从 Validation 标签拟合参数。

4 bit 码真实打包为每字节两个无符号码，按固定张量顺序低位码在前；8 bit 每码一字节。理想 FP32 恢复误差作为量化器诊断；主输出指标必须使用**真实打包/解包可复现的 BF16 恢复值**，不能给模型使用理想恢复值却按整数载荷计算预算。

### 21.4 单点干预与固定前缀

先用原 B1 ID 完成无干预 Prefill/回放。在指定检查点暂停；每个模型分支均从**相同的原始历史状态、相同当前输入 Token**开始，只让目标层 Attention 接收到指定 Head 的量化恢复副本。该物理 KV Head 对应的四个 Query Head 一起受影响，不重复计四份物理 KV。当前新行仍为 BF16，所有可见位置的长度、顺序、因果关系和掩码不变。

分支执行完整模型的这一个 Decode Forward，目标层之后的隐藏状态和 Logits 允许自然变化；分支新增 Cache 随后丢弃，恢复基线检查点后再执行下一情况，不能让前一分支污染后一分支。原始 Prompt/历史 Cache 不写回量化值；后续基线轨迹继续使用原始状态。只有无干预回放核对原 B1 Top-1；干预分支的 Top-1 变化是研究结果，不能沿用原 Runner 的严格匹配断言将其报成执行失败。

局部对照复用同一基线 Query/K/V，直接计算目标 Head 的反事实 Attention；模型分支用于检查该局部扰动传到最终输出的后果。两层都不是持续压缩 Cache 的长程回放，也不是自由生成质量测试。不得因每个单点都变化很小，就推断多 Head 同时压缩或误差累积也很小。

现有 `AttentionProbe` 保持只读约定，不能从回调原地修改原张量。后续实现可复用其观测位置和现有回放逻辑，单独隔离临时干预，并在结束后恢复原 Attention 调用；不复制整份模型 Forward、不修改 KV-Base 或默认模型执行行为。检查点分支控制可在实验 Runner 中最小增补，避免让其他研究流程承担新接口。

### 21.5 误差定义与汇总

令目标 Head 为 h，对应四个 Query Head 集合为 `G(h)`；所有概率均在**完整可见域**归一化。使用实际模型 scaling；下式以标准 `1/sqrt(D)` 表示：

$$A_q=\operatorname{softmax}(Q_qK_h^\top/\sqrt D),\qquad O_q=A_qV_h.$$

K 分支使用 `A_hat=softmax(Q K_hat^T/sqrt(D))`、`O_hat=A_hat V`；V 分支使用 `O_hat=A V_hat`，A 应保持原值。一次只改变一个侧，不能把 K/V 同时扰动的误差混入结果。

| 指标 | 精确定义与解释 |
|---|---|
| 表示 NMSE，`e_X` | `sum((X_hat−X)^2)/sum(X^2)`，仅在指定 Head 的 Q 个量化位置计算；K/V 分开，BF16 实际恢复为主，FP32 恢复另列。它是本轮新指标，不替换 A1 的 `e/s` |
| 局部 Attention Output NMSE，`e_O` | `sum_{q in G(h)} sum((O_hat_q−O_q)^2) / sum_{q in G(h)} sum(O_q^2)`，在四个 Query Head 合并后、输出投影前计算；另保留每个 Query Head，不能把四份概率先平均再计算 |
| K 分支 Attention KL | 四个 Query Head 的 `KL(A_q, A_hat_q)` 均值，第一个参数为参考分布，用于解释 Key 扰动；V 分支以 A 不变作为正确性检查 |
| 最终预测 KL，主模型指标 | `KL(p_BF16, p_branch)`，第一个参数为参考分布，p 为相同检查点整个词表的温度 1 softmax；以 FP32 log_softmax 计算并稳定汇总，不用 Top-K 词表近似，不对概率任意加 epsilon |
| Top-1 与 ΔNLL，辅助 | 相对基线的 Top-1 是否改变；`ΔNLL=−log p_branch(y)+log p_BF16(y)`，`y=generated_ids[s+1]`。y 是原模型续写，非任务真实标签，不能称任务准确率或真实语料 PPL |

表示/Output 分母为零时保留绝对平方误差并标记相对值无效，不以任意常数造比值。理论非负的 KL 如有小负值，记录其量级并按预先数值容差判定，不直接裁零掩盖错误。旁路与重复基线的差异单列为数值背景，不直接从量化误差中相减。

以 K/V、4/8 bit、条件、Layer×Head 分开汇总，保存均值、输入内 Head P90 和最差坐标。局部范围与四层整模范围分开，不能用全部 256 个局部 Head 代替模型输出样本数。额外考察 `e_X` 与 `e_O`/预测 KL 的关系：同位宽结果只能称同成本扰动；若重建误差不同，不宣称已完成严格等重建误差实验，也不因低有效秩就预先判为不敏感。

**跨输入保持性主口径：**Calib 中六条件等权，分别以局部 `e_O`、模型预测 KL 建立逐层八 Head 的 4 bit 敏感性画像；局部主画像也只用 RULER `s=5`、其余任务 `s=31`，`s=255` 单独作晚期对照，不混入拟合。8 bit 独立报告，不混合排名。冻结后与每条 Validation 的同层八 Head 排名计算 Spearman，报告逐条件值、条件等权均值、中位数和负相关条件数；并比较 Calib 预先确定的最高/最低各两个 Head 在 Validation 的损失，列出反转。并列排名用平均秩，常量向量标记无效；最高/最低组在截断边界并列时按较小 Head ID 决定，并标明并列。不做跨层幅值混合的相关。PG19 按来源配对保留两个长度，不把 Head/Step 当独立来源做显著性检验或夸大置信区间。

### 21.6 实际字节预算：码、参数、未量化数据和工作区

以下预算按未压缩的实际布局字节计算，不按 NPZ 大小，也不只计算 bit×元素数。设检查点已消费 `g=s+1` 个生成 Token，`n=T+g`，D=128；只量化某侧的一个 Head。两种分组的组数恰好均为 `QD/32`，故：

$$B_{codes}(b)=\left\lceil QDb/8\right\rceil,\quad
B_{stats}=8QD/32,\quad
B_{side}(b)=B_{codes}(b)+B_{stats}+2D(n-Q).$$

最后一项包含该侧全部保护区、Prompt 残余和新增 Decode 行。未量化的另一侧及其他 Head 均按 BF16 支付；单 Head/单侧干预的完整 KV 账本为：

$$B_{request}=4nLHD-2nD+B_{side}(b)+B_{request,meta}+B_{padding},\qquad L=32,H=8.$$

请求长度状态 T/g 各 uint32，共 8 B，各方案按相同实际需求支付；独立请求头按 64 B 对齐，不能将完整研究 JSON 算作硬件元数据。码、统计、BF16 首段/尾段分别连续存储，流起点按 64 B 对齐，实际填充另列；当前 D/G/Q 设置下各数据流长度本身为 64 B 的倍数。模型侧仅新增 16 B 编码格式头和 8 B 的单点 Layer/Head/量化侧/位宽描述，各候选静态块合计对齐至 **64 B**；BF16 基线不收取这项新增费用。没有拟合基、均值表、码本或异常值侧表。实际实现若需要其他布局字段，必须列入账本并在 Validation 前冻结，不能把开销藏在控制逻辑中。

每 Head、32 个量化位置的对照如下，已含量化侧全部 FP32 m/a，不含共同保护区/请求头及静态 64 B：

| 情况 | K 字节 | V 字节 | 合计 |
|---|---:|---:|---:|
| 原始 BF16 | 8,192 | 8,192 | 16,384 |
| K4 / V 保持 BF16 | 2,048 码 + 1,024 统计 | 8,192 | 11,264 |
| K8 / V 保持 BF16 | 4,096 码 + 1,024 统计 | 8,192 | 13,312 |
| K 保持 BF16 / V4 | 8,192 | 2,048 码 + 1,024 统计 | 11,264 |
| K 保持 BF16 / V8 | 8,192 | 4,096 码 + 1,024 统计 | 13,312 |

这里的 32 行量化块不同于 B1 的 16 Token 逻辑 Page，不修改 B1 Page/RCO 定义。相同输入、量化侧和位宽下，不同 Head 的真实字节相同；本分组下 K-only 与 V-only 的相同位宽预算也相同，可直接比较相同成本的输出影响。**4 bit 不等于该侧缩至原来的 1/4**：每 32 行还需 1,024 B 统计，加保护区后更高。

例如 T=32,768、g=0 时，原始全模型 KV 数据为 4,096 MiB；单个 Head 的 K4 或 V4 实际省 **4.980 MiB**，全模型仅约 **0.122%**，再扣新增布局费用。单点干预的目的在于识别敏感性，这个比例既不是完整压缩方案的收益，也不能被写成全部 Head 都同样安全的依据。本轮不实施混合精度预算；将来若比较 Head-aware 分配，必须以全模型统一精度为对照，同时支付模型常驻表、全部请求数据/统计/残余/对齐及工作区，不能只与 BF16 比较或只匹配码载荷。

还必须分开报告三类成本：

1. **编码布局：**模型新增字节、每请求编码 KV 字节、保护区/统计/元数据/填充及合计；在至少一个真实长 Prompt 上实际打包/解包并核对长度，不长期保存完整编码副本。
2. **研究实现：**原 BF16 Cache、量化恢复副本、分支状态和 FP32 计算缓冲造成的实测 GPU 峰值、墙钟时间；按块计算统计并顺序执行分支，不持有全部分支或检查点 Cache。它们不是压缩部署后的显存/时延收益。
3. **未来消费路径：**若每步先恢复 BF16 到片外工作区，再由 Attention 读取，必须同时计入压缩读取、BF16 恢复写入和再次读取；只有明确融合到片上消费的数据流后，才可讨论避免这些搬运。本轮无新 Kernel、真实 LPDDR 流量或加速结论，量化也不自动减少 Dense QK/AV 的运算量。

### 21.7 验证顺序、判定与结果保留

按以下顺序推进。用户已批准方案，本轮仅完成第 1 项及所需核心代码，第 2/3 项尚未启动：

1. **小模型与算子正确性。** 验证分组/常量组/舍入/4 bit 打包与解包、实际字节、未满组处理；旁路不改变结果，单点替换不改变其他 Head 或保护区，完整可见域和四个 Query Head 映射正确。局部公式与原 SDPA 的目标 Head 输出在对应精度容差内一致；V-only 不改变 Attention 概率。检查所有分支从同一历史出发，结束后基线 Cache/后续回放恢复一致。
2. **六条 Calib。** 完成全部局部及四层模型对照，测量实际运行/内存成本和重复基线数值背景，保存敏感性画像。先确认计算可执行、扰动可与背景区分；若有实现错误先修复并完整重算受影响 Calib，不以改位宽/范围消除不利结果。
3. **冻结后六条 Validation。** 冻结样本、检查点、层/Head、量化器、指标、字节布局和 Calib 画像，再按相同流程核验排序与最差 Head。不得据 Validation 调整保护区、选择更好层、换指标或重新拟合画像后仍称本轮通过；如确需新方案另行讨论。

本轮判定区分三件事：数值/隔离/字节核验是否正确；是否观察到高于背景且跨输入保持的 Head 输出敏感性差异；是否已有可部署的预算收益。第三项在本轮仍为**未验证**。不预设一个未经任务质量标定的 KL“安全阈值”，也不要求 4 bit 一定成功：如损失均低于背景、排序不稳定、局部差异未传到模型输出，或最差 Head 明显恶化，直接保留这些结果。只有输出敏感性有可重复信号，才值得另行设计同总字节的组合分配与持续回放/任务质量验证；不自动扩样或进入硬件设计。

实现时复用现有 `runtime/model.py`、B1 输入索引、固定 ID 回放、Attention 观测位置、资源计量和 common I/O；量化算子/干预生命周期放 runtime，局部统计放 collectors，分支组装放现有 runners 体系，离线画像汇总放 analysis，CLI 保持薄入口。按实际需求最小增补，不新建通用实验框架，也不通过改只读 Probe 的语义混入干预。

结果写独立 `data/analysis/v3_head_quant_sensitivity_<版本>/`，保留一份配置/冻结决策、Calib/Validation 逐样本紧凑指标、敏感性画像、实际字节/资源汇总及文字结论。只保存上述标量/小数组、必要的预测 ID，不落盘全词表 Logits、Attention 矩阵、完整 Q/K/V 或逐分支 Cache，不新增 Hash 清单。数值包按上述有限矩阵预计在数十 MiB 内，先预留 100 MiB；GPU 时间/峰值在 Calib 实测，不承诺未经测量的值。旧 V2/V3 工件保持原样，研究结论继续写入本报告。

### 21.8 核心代码与小模型验证（2026-11-17）

本轮按授权只实现量化、单 Head 干预与检查点分支，不启动真实模型：

- `runtime/kv_quantization.py`：固定 G=32 的 K/V 分组 min/max 量化，4/8 bit 真实打包/解包、FP32 m/a、分块恢复及第 21.6 节字节账本；常量组不加 epsilon，组尾/保护区由固定 Prompt 范围控制。
- `runtime/head_intervention.py`：仅为目标 Attention 模块临时选择独立后端，模型和其他层继续使用原 SDPA；只替换目标侧的张量副本，保持原 Cache 和只读 Probe 语义。退出或异常时恢复目标层配置并移除临时后端。
- `runners/quantization_runner.py`：每个检查点从相同历史执行独立基线及各单点分支，计算完整词表 KL、Top-1 和 ΔNLL；分支结束后恢复所有层的原 K/V 引用。复用 `b2_runner.teacher_forced_replay`，仅增补可选的 `before_decode(step, cache)` 回调，默认路径不变。

检查点恢复针对当前 Transformers 5.2.0 的标准非 offload `DynamicCache/DynamicLayer`：其追加操作用 `torch.cat`，原历史张量不变，所以可恢复引用而无需预先深拷贝完整 Cache。**追加仍会分配新张量，且恢复前保留原历史引用；不宣称额外显存为零或已降低峰值。** 不支持滑动窗口/静态 Cache，后续真实模型资源需另测。默认只返回紧凑分支结果；完整 Logits 仅在小模型测试显式开启并复制到 CPU。

最终预测比较采用 FP32 log-softmax、FP64 加权求和；负 KL 的绝对容差固定为 `1e−6`。容差内保留原负值及舍入标记，超出则报错，不裁零，也不把这一数值容差解释为模型质量阈值。

本地 CPU 的 **45 项相关测试通过**，包含新增量化/干预/分支测试，以及原 B2 Runner、只读 Probe、V2 Runner、Pre-RoPE 编码和模型加载回归。小模型采用两层、两个 KV Head、每个对应四个 Query Head、D=32，分别验证 FP32/BF16；使用含中段残余的 205 Token Prompt 和多个 Decode 检查点。核验了独立分组参考、舍入/常量组、整数码物理字节、完整可见域 QK/softmax/AV、保护区/新行/非目标 Head 不变、原历史不被改写、分支换序、异常后的恢复及只做一次 Prefill。带分支的主回放 Logits 与原回放逐项相同，旁路分支误差为零。

上述初步验证只覆盖算子与干预链路；当时尚未完成全 Head 局部统计和正式落盘入口。后续补全见第 21.9 节；真实六条 Calib/Validation 和压缩质量/部署收益仍未验证，未改变第 21.1～21.7 节的范围、位宽、指标或评价顺序。

### 21.9 全 Head Collector、结果 Writer 与 CLI（2026-11-17）

已接通完整的小规模执行入口，仍只在本地小模型验证：

- `collectors/quantization_sensitivity.py`：每层逐 KV Head 计算 K4/K8/V4/V8 的表示误差、完整可见域 Attention KL 和 Output NMSE，保留每个 Query Head 的误差与能量；BF16 实际恢复值进入 FP32 QK/Softmax/AV，平方误差以 FP64 汇总。另记录 FP32 公式与独立 SDPA 对照的数值背景，不直接从扰动误差中相减。零能量比值保存为 NaN 并附有效标记，JSON 汇总为 null。
